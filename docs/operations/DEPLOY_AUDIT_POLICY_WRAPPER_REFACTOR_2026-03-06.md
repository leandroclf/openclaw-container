# Deploy Audit Policy Wrapper Refactor - 2026-03-06

Purpose: define the exact refactor for the internal OpenClaw job `Deploy log capture and status audit` so it stops owning raw collection and keeps only policy, summary, and escalation behavior.

## Current issue

The internal job currently owns both:

1. raw data collection
2. policy/orchestration

That makes it impossible to retire the duplicated collection path safely.

The collection side is now already covered in production by Agent OS:

- `product_progress_snapshot`
- `github_ci_status_collect`

So the internal job should be reduced to a wrapper role.

## Target ownership after refactor

### Agent OS `prod-observe`

Owns:

- `daily_ops_state_lint`
- `product_progress_snapshot`
- `github_ci_status_collect`

Produces:

- `deploy-status.json/.md`
- `ci-regression-watchdog.json/.md`
- `product-code-progress.json/.md`
- Agent OS DB/events/reports

### Internal OpenClaw cron

Owns only:

- reading the already-produced artifacts
- applying `ALERT_OWNERSHIP_POLICY.md`
- appending policy outcome to `daily-summary.md`
- announcing/escalating if necessary

## Exact refactor target

Replace the internal job’s current payload logic:

- remove direct execution of:
  - `python3 tools/github_ci_status.py`
  - `python3 ops/multiagent/delivery/scripts/product_progress_snapshot.py`

Replace it with a thin wrapper script, for example:

- `ops/multiagent/delivery/scripts/deploy_audit_policy_wrapper.py`

## Responsibilities of the new wrapper

The wrapper should do exactly this:

1. load:
   - `ops/multiagent/delivery/deploy-status.json`
   - `ops/multiagent/delivery/ci-regression-watchdog.json`
   - `ops/multiagent/delivery/product-code-progress.json`
2. validate freshness window
3. apply `ALERT_OWNERSHIP_POLICY.md`
4. append structured summary text to `daily-summary.md`
5. decide whether an AUTO_ALERT or HUMAN_ALERT must be emitted

It should **not**:

- call GitHub APIs directly
- call `git fetch`
- regenerate the collection artifacts
- mutate product repos

## Freshness gate

The wrapper needs a simple freshness rule, otherwise it could read stale data and make bad decisions.

Recommended rule:

- collection artifacts must be newer than `90 minutes`

Required files:

- `deploy-status.json`
- `product-code-progress.json`

Optional but expected:

- `ci-regression-watchdog.json`

Behavior:

- if freshness passes:
  - continue with policy evaluation
- if freshness fails:
  - write a `HARD_BLOCKER` note to `daily-summary.md`
  - do not emit fake CI conclusions
  - announce that the collection layer is stale

## Exact output contract for the wrapper

Append a section in `daily-summary.md` with:

- timestamp
- artifact freshness
- CI status summary
- product progress summary
- policy decision
- ownership decision
- next action
- agent/skill/workflow metadata

Recommended section shape:

```markdown
## CI/CD Status Audit
- Collection freshness: OK / STALE
- Deploy status source: deploy-status.json
- Product progress source: product-code-progress.json
- Policy applied: ALERT_OWNERSHIP_POLICY.md
- Decision: monitor / AUTO_ALERT / HUMAN_ALERT
- Owner(s): ...
- Next action: ...

### Meta-Information
- Agent: infra-analyst + devops-ci-cd-specialist
- Skill: n/a
- Workflow: Deploy Audit Policy Wrapper
```

## Refactored internal cron payload

After implementation, the internal job payload should become conceptually:

```text
Atue como infra-analyst + devops-ci-cd-specialist. Leia os artefatos já produzidos em:
- ops/multiagent/delivery/deploy-status.json
- ops/multiagent/delivery/ci-regression-watchdog.json
- ops/multiagent/delivery/product-code-progress.json

Valide freshness dos artefatos. Aplique a política
ops/multiagent/delivery/ALERT_OWNERSHIP_POLICY.md.
Registre decisão e evidências em ops/multiagent/delivery/daily-summary.md.
Se houver 2-4 falhas consecutivas: AUTO_ALERT.
Se houver >=5 falhas consecutivas: HUMAN_ALERT.
Não reexecute coleta bruta nesta rotina.
Registrar Agente + Skill + Workflow.
```

## Safe rollout plan

### Step 1

Create the wrapper script in the workspace repo only.

### Step 2

Run it manually against the artifacts already generated by:

- internal job
- Agent OS `prod-observe`

### Step 3

Edit the internal OpenClaw cron payload so it uses only the wrapper.

### Step 4

Observe at least 2 internal cron cycles with:

- fresh artifacts
- correct `daily-summary.md` append
- correct AUTO/HUMAN decision logic

### Step 5

Only after that, consider the collection side of the internal job fully retired.

## Why this is the correct cut

This refactor:

- removes duplicated collection work
- preserves current escalation semantics
- keeps the risky part (`policy + escalation`) where it already works
- creates a clean boundary between observation and orchestration

That is the lowest-risk path to continue the migration.
